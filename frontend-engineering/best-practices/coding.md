# Minimal, Maintainable Coding
- Understand the current code and reuse existing patterns before changing it.
- Make the smallest safe diff that meets the requirement; do not refactor unrelated code.
- Prefer readable, direct solutions over speculative layers, libraries, or abstractions.
- Preserve backward compatibility and existing contracts unless the task requires a change.
- Handle realistic failures explicitly. Do not swallow errors or silently invent defaults.
- Review the diff, remove accidental changes, and explain important tradeoffs.
